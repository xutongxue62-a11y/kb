初稿日期：2026-11-13。更新：2026-11-14。版本：v0.9。当前阶段：按用户新想法切换为“原始人大作战”，主角改为原始人、敌人全部改为恐龙，重绘第一版方向样张；沿用已基本认可的简洁画风。正式实现仍使用 Godot 或 Unity 等游戏引擎，具体引擎未选定。五武器槽、二/三武器联动和阵型框架保留，文件名保留为原入口。

**最新题材变更：用户要求改为“原始人大作战”，主角换原始人、怪物都换恐龙，画风保持现在的简单风格。本轮重绘主角、四类恐龙及配套场景；新题材由用户提出，新造型仍是第一版候选。本轮不编程或创建工程，旧角色、现代武器与战斗样张保留为历史资源。**

美术探索最新约束：平面顶视角、非像素、少量大色块，避免 2.5D、机器人结构和过度可爱。新原始人方案沿用圆润单体头身、眼鼻嘴与四个分离小圆手脚，通过头发、胡须和兽皮表达身份；恐龙通过嘴、尾、足、角或甲壳形成不同轮廓，不照搬主角的悬浮圆肢体。见[当前美术方向](美术风格探索/2026-11-13_圆身角色_当前方向.md)及[原始人大作战重绘样张](美术风格探索/2026-11-14_原始人大作战_风格探索_v0.1/2026-11-14_原始人大作战_探索说明.md)。旧圆身角色不再是当前主角，新图保存不代表用户已验收。

## 1. 本次明确的项目方向

| 项目 | 立项约束 |
| --- | --- |
| 类型 | 参考《土豆兄弟》的俯视角竞技场刷怪肉鸽，保留局内成长与搭配选择 |
| 题材 | 用户要求改为原始人对抗恐龙；主角原始人，敌人全为恐龙，保持简单的平面 2D 画风；具体新造型待反馈 |
| 节奏 | 进场即进入战斗，目标是快节奏、操作顺手、成长明显的爽感 |
| 空间 | 一张简单开阔的竞技场，优先减少地形和探索系统的制作量 |
| 四个重点 | 核心玩法、美术风格、怪物设定、武器及其搭配与成长 |
| 角色数量 | 首版先做一个角色，其他角色后续再讨论 |
| 武器持有 | 最多同时装备五把武器，覆盖此前三槽建议；开局仍只有一把最普通的基础武器；五是同时持有上限，不是武器库总量 |
| 攻击方式 | 近战武器围绕角色旋转攻击，远程武器自动射击 |
| 自动选目标 | 每把远程武器先筛选自身射程内的有效目标，默认选最近目标；可开启精英优先，仅在自身射程内存在精英时优先选最近精英，否则选最近普通目标 |
| 阵型 | 采用推荐的展开扫荡/收束集火方向；阵型不得绕过射程检查或改变最近/精英优先的选目标规则 |
| 成长表现 | 武器升级应包含形态或攻击方式的变化，逐渐增强；Buff 丰富构筑与战斗体验 |
| 普通武器升级 | 用户明确希望通过重复选择、合成同名武器来升级；具体副本数量与等级门槛仍需设计 |
| 跨武器组合 | 指定两把或三把武器可触发联动伤害；各原武器及等级保留，各占原武器槽，联动不新增武器槽；沿用上一轮取消融合武器的决定，本轮口语中的“两两/三个融合”按联动理解 |
| 武器池扩展 | 当前少量武器先验证，后续可增加武器；不把此前六件候选作为永久数量上限 |
| 支援内容 | 用户希望纳入无人机、宠物等；具体数量、装备槽和生产阶段尚未确认 |
| 制作目标 | 一个人配合 AI，按正常游戏制作流程完成能实际游玩的作品，并保留制作与迭代证据 |
| 技术路线 | 用户明确要求用 Godot、Unity 等游戏引擎正式制作；具体引擎待玩法视角、美术方向与资源规范明确后选定 |
| 目前状态 | 原始人、四类恐龙与配套场景已重绘为第一版候选；旧角色和现代武器图片转为历史参考；未创建 Godot/Unity 正式工程，尚无实机结果 |

题材已明确切换为原始人对抗恐龙；地图的具体形状与场景细节、武器种类总量、支援槽及具体联动配方仍待细化。美术采用平面顶视角、非像素 2D 表现，“同时最多五把”、初始一把、二/三武器联动和阵型框架保持不变。此前机器人题材、旧圆身角色及现代武器造型均为历史参考，不作为新题材已确认的正式资源。

用户希望在保持上述基础框架的同时，寻找玩法差异；也愿意通过美术风格、打击特效、动感、数值和机制提高辨识度。保持五武器、环绕近战、自动远程和独立成长的基础，重点验证联动与阵型的实际体验。

最新决定已解决联动与融合的取舍：每把原武器保留自己的等级、外形和攻击价值，继续用同名副本升级；联动在已有武器之间增加伤害或特殊触发，具体规则仍需设计。“融合产物解锁后加入武器池”是此前已撤销的思路，不能继续作为当前方案。

用户已选择阵型作为额外战斗机制。怪物互相利用、擦险充能等仍为未采用候选，不同时加入首版。五槽可支持一组三武器联动与一组二武器联动；具体配方要根据武器角色设计，不要求任意组合都生效。

## 2. 先定义玩家要得到的体验

玩家快速进入战斗，依靠走位和核心操作处理怪群；获得升级后，攻击方式或战斗策略出现可感知的变化；随后应对更强的怪物组合，形成自己的打法，完成一局后愿意尝试另一种搭配。

拟采用的完整循环：用一把基础武器开局 → 进场开打 → 击杀并获得成长机会 → 获得或升级武器（同时最多五把），选择 Buff → 激活二/三武器联动、根据战况切换阵型 → 挑战更强怪潮和 Boss → 结算与直接重开。支援内容在确定装备规则后接入相应成长节点。

基础攻击采用环绕近战与自动远程，额外主动操作为一键阵型切换；具体按键、资源与数值在原型前落实。起始配置提供默认基础武器，尽量减少进入战斗前的准备操作。

### 快节奏的初始验收目标

以下时间是本项目的设计目标，供原型验证，不是行业标准或已达到的成绩：

- 进入战斗场景后约 5 秒内开始有效交战。
- 前 30—60 秒能获得并感知第一次有意义的成长变化。
- 前 2—3 分钟能看出某种打法正在形成；每次升级不必都出现新特效，但重要升级应改变行动或攻击表现。
- 首个完整作品版仍按约 8—10 分钟规划一局；中间安排压力、变化与短暂恢复机会。

击杀爽感由命中反馈、攻击节奏、目标反应和成长共同构成。怪物数量多、特效多只是手段；必须同时检查操控、危险可读性与实际性能。

## 3. 本轮明确的战斗规则与补充提案

### 选目标和射程

每把远程武器独立处理：先按当前武器及当前阵型的实际射程筛选存活且可攻击的目标，再按距离排序。默认攻击最近目标；精英优先开启时，存在射程内精英则选其中最近者，否则回到最近普通目标。射程外精英不参与选择，无有效目标时暂不发射。Boss 是否归入高优先级类别在敌人分类表中明确。

环绕近战按实际攻击轨道与碰撞范围命中敌人，不为追逐精英而脱离轨道。精英优先设置主要作用于需要选择目标的远程攻击；特殊联动的后续目标规则另写在配方中。

### 展开与收束

- 展开扫荡：近战使用较大的环绕半径；支持改变弹道的远程武器采用较宽覆盖，例如宽扇形霰弹、宽而短的火焰。
- 收束集火：近战缩小环绕半径，形成近身密集攻击；支持改变弹道的远程武器采用较集中覆盖，例如窄扇形霰弹、窄而长的火焰。
- 两种阵型都遵守同一选目标规则。此前“展开时故意分散攻击不同目标”的提案撤销。
- 每把武器的具体阵型差异由武器设计卡确定，保留其攻击身份；先比较范围、风险与输出分布，避免把一种阵型做成无代价的全面强化。

### 联动配方的工作建议

以下为题材变更前的历史功能示例，仅用于理解联动，不是“原始人大作战”的当前武器表。石器武器映射与具体配方需另行设计；新题材造型样例见[本轮说明](美术风格探索/2026-11-14_原始人大作战_风格探索_v0.1/2026-11-14_原始人大作战_探索说明.md)。

| 配方 | 示例效果 | 用途 |
| --- | --- | --- |
| 手枪 + 环绕飞刀 | 按固定射击次数强化下一发，发出穿透飞刀弹；两把原武器继续攻击 | 二武器基础联动 |
| 手枪 + 环绕飞刀 + 喷火器 | 在飞刀弹上继承灼烧并增加火焰效果 | 相应二联动的三武器进阶 |
| 电弧枪 + 锯轮 | 电枪给目标施加电荷，锯轮命中后触发短程电弧 | 独立的二武器联动 |

上述五件样本可以同时展示“三件联动 + 两件联动”。满足相应三联动时，同一触发链用其进阶效果结算，继承基础二联动的效果，不再额外重复生成一份基础攻击；独立触发链仍可并行。联动额外攻击不再次触发同一联动链，冷却、伤害系数、事件归属和例外在配方表明确，防止无限接力。

原武器照常通过重复选择升级，联动强度和表现从参与武器的成长中取得，不产生需要单独抽取升级的“联动武器”。具体继承公式与阶段门槛在数值初值表落实。

首轮验证建议覆盖五武器同时攻击、一组三联动与一组独立二联动、阵型切换、射程外精英与近处普通怪并存等场景，确认武器仍清楚可辨、选目标正确、联动可读且阵型存在有效取舍。

## 4. 四个重点分别怎样设计

| 重点 | 必须确定的内容 | 最先做的可验证样本 | 判断依据 |
| --- | --- | --- | --- |
| 核心玩法 | 玩家持续操作什么、何时做主动决策、成长怎样改变打法、失败怎样产生、与近似作品的差异 | 一个角色、一种武器、一种敌人的短原型 | 几秒内的动作有反馈，几十秒的成长有变化；独特机制会改变行为且没有明显操作负担 |
| 美术风格 | 题材、视角、轮廓、色彩、材质、动画、特效与 UI 的统一关系 | 同一镜头下的角色、敌人、武器及命中/受击效果样本 | 一眼分清敌我和危险；美术与玩法信息一致；样本制作成本可接受 |
| 怪物 | 战斗职责、移动与攻击、预警、弱点、掉落、数值、出现时机与组合 | 一个追击敌人，再加一个能打破当前单一策略的敌人 | 玩家能看懂并应对；组合改变压力与决策；造型能提示职责 |
| 武器 | 攻击动作与轨迹、射程、攻击节奏、适用目标、短板、成长质变、反馈与搭配 | 先验证一件基础武器，再比较另一件攻击范式不同的武器 | 两件武器会改变站位、目标选择或操作节奏；成长可见；各自有适用情境 |

武器与怪物的功能草案应先于正式造型生产；美术方向确定后，再细化模型/图像、动画、特效与声音。这些内容需要在引擎中互相验证。

### 武器设计卡

每件武器至少写清：战斗定位、基础攻击、攻击范围与节奏、擅长和不擅长的情况、一项代表性成长变化、与怪物的互动、造型和音画反馈。先把少量武器做出差别，按样本成本确定首版数量。

### 怪物设计卡

每种怪物至少写清：给玩家制造哪种压力、移动和攻击流程、预警与躲避方式、基础参数与掉落、何时出现、与谁组合、轮廓与颜色识别。首版约 4 种普通敌人的职责可先按下面的候选划分：

- 追击型：提供基础包围压力，让玩家理解走位、聚怪和清怪。
- 冲锋型：通过明显预警后的快速移动，要求玩家改变路径。
- 远程型：在近战怪群之外制造方向压力，要求观察与目标选择。
- 耐久型：让集中输出和持续输出有价值，改变敌群处理顺序。

这些是功能角色，不是最终怪物题材。Boss 以少量可辨识招式综合考验已有操作；若所选核心机制依赖击杀补给，Boss 战必须持续提供相应补给来源。

## 5. 正常制作流程在本项目中的执行顺序

| 顺序 | 当前要完成的工作 | 交付物 |
| --- | --- | --- |
| 1. 立项与核心策划 | 体验、差异、操作、武器与怪物职责、成长、胜负和首版范围 | 一页玩法稿、规则与数值初值、武器/怪物草表、原型验收条件 |
| 2. 核心原型 | 在原型前落实引擎与设备，用简单图形实现和试玩主循环 | 可玩原型、反馈、问题和修改记录 |
| 3. 美术预研 | 定风格和资源规范，验证角色、敌人、武器与特效样本 | 美术方向稿、引擎中的样本、资产规范 |
| 4. 内容与战斗编排 | 细化武器和升级、敌人和 Boss，安排竞技场尺寸、怪潮与强度 | 武器表、怪物表、升级表、波次与 Boss 行为表 |
| 5. 小段完整样板 | 整合程序、美术、战斗、UI、声音、暂停、设置、结算和打包 | 约 3—4 分钟、能从开局走到结算的流程样板 |
| 6. 正式内容制作 | 按样板补齐完整短局范围，控制新增内容和成本 | 约 8—10 分钟的首个完整作品版 |
| 7. 试玩与优化 | 检查理解、手感、平衡、性能、功能与兼容；修改后复测 | 试玩数据和观察、缺陷单、版本前后对照 |
| 8. 作品交付 | 打包、操作说明、实机视频、个人贡献、AI 协作及制作复盘 | 体验包、视频、工程与资源归档、作品说明 |
| 9. 公开发布与维护 | 准备商店物料、Demo、审核、发布和更新，并处理玩家反馈 | 发布构建、商店页面、反馈与版本记录 |

此表合并展示总路线中的阶段，未减少程序、UI、音效、数值或测试工作。玩法与武器/怪物职责先确定，美术样本成立后扩大制作。数值、场地尺度、测试和技术验证从原型起参与，随后反复迭代。版本管理、备份、素材来源及成本记录贯穿制作。

## 6. 眼前这一阶段的完成条件

当前主框架已收敛为五武器、二/三武器联动和阵型切换；继续补齐武器设计卡、联动配方、数值初值、Buff 与支援规则、敌人职责、胜负及最小验证场景，形成可供原型实施的完整玩法稿。

同时交付一套最小原型场景与初值，验证操作、成长和差异点。玩法稿完成和原型验证通过是两个不同里程碑；美术方向与正式资源生产在后续阶段承接。
